# Linux Push-to-talk

Приложение использует GlobalShortcuts Portal v1 для BindShortcuts и событий удержания.
ConfigureShortcuts включается только для v2. Windows PTT и аудиопротокол не меняются.

## Идентификация

Linux-пакет устанавливает `bundle/linux/ru.cheenhub.desktop` в
`/usr/share/applications/ru.cheenhub.desktop`. Это desktop entry для идентификации
в Host Portal Registry. `NoDisplay=true` исключает второй пункт запуска в меню:
основной launcher `cheen_hub.desktop` по-прежнему создаёт Dioxus bundler.
Runtime ничего не создаёт в каталоге applications и регистрирует новое выделенное
D-Bus-соединение перед первым portal-вызовом.

Для разработки один раз явно установите отдельную запись:

```sh
install -Dm644 bundle/linux/ru.cheenhub.Development.desktop \
  "${XDG_DATA_HOME:-$HOME/.local/share}/applications/ru.cheenhub.Development.desktop"
```

Добавьте в локальную `.env` `CHEENHUB_PORTAL_APP_ID=ru.cheenhub.Development` либо
задайте это значение в окружении запуска клиента. Запись скрыта из меню и имеет
собственный app ID: разрешения разработки не конфликтуют с установленным пакетом.
Host Portal Registry должен видеть файл в своих XDG data directories; изменение
только окружения клиентского процесса не меняет каталогов уже работающего portal.
В sandbox используется идентичность sandbox, Registry не вызывается.

## Ограничения контрактов

`Available` означает успешный CreateSession, но не разрешение передавать звук.
`Ready` требует успешного BindShortcuts. Без подтверждённой привязки восстановление
переходит в `BindingRequired` и предлагает явное «Назначить».

При входе в голосовую комнату и после перезапуска ListShortcuts проверяет
системное действие. Если действие найдено либо локальная настройка содержит
ранее подтверждённое назначение, BindShortcuts подключает его к новой сессии.
В GNOME сохранённое действие подключается без повторного выбора сочетания.
При первом запуске без назначения автоматический bind не вызывается.
API не предоставляет silent-only флаг: при удалении системной привязки или
отзыве разрешения backend может запросить подтверждение даже при наличии
старой локальной настройки. Пока подтверждение не получено, gate закрыт.

Проверка поддержки имеет состояния Pending, Available и Unavailable.
Захват может стартовать во время Pending: Monitor принимает lease, но не
разрешает звук до регистрации сессии и нового Activated. Завершение проверки
и восстановление D-Bus не требуют перезапуска микрофона.

Технические D-Bus method calls ограничены пятью секундами; открытие соединения,
Registry и CreateSession также ограничены общим тайм-аутом запуска.
ListShortcuts ожидает ответ не более пяти секунд, ConfigureShortcuts ограничивает
только открытие системного окна. BindShortcuts не ограничивает ожидание
пользовательского решения; тайм-аут method call не ограничивает асинхронный
Response системного диалога. Технический тайм-аут закрывает gate и запускает
восстановление соединения при наличии capture-потребителя.

На v1 повторное «Назначить» возвращает сообщение о системных настройках
без BindShortcuts для открытия UI. В живой сессии привязка сохраняется;
автоматическое подключение сохранённого действия остаётся доступным.

ConfigureShortcuts возвращается при открытии окна и не сообщает системную отмену.
Изменение ShortcutsChanged автоматически завершает назначение; при отмене или
отсутствии изменений пользователь нажимает «Готово» либо «Отменить» в CheenHub.
Нет тайм-аута, удаляющего старую привязку или считающего молчание отзывом разрешения.
Пока назначение ожидает завершения, передача приостановлена. Если потребителей нет,
сессия закрывается сразу после завершения или отмены; системная привязка сохраняется.
Изменения из GNOME Settings приходят только в живую сессию. При отсутствии PTT
сессии приложение не перехватывает сочетание и узнаёт актуальное значение при
следующем автоматическом подключении.

При аварийном завершении самого worker старый Monitor остаётся закрытым.
UI сохраняет указание перезапустить микрофон даже после повторного probe:
новый capture получает Monitor нового worker, после чего сохранённое сочетание подключается
автоматически. Потеря D-Bus без аварии worker не требует замены Monitor.

## Ручная проверка GNOME 51

1. Установить Linux-пакет с desktop entry; запустить приложение без временных launcher.
2. При первом запуске выбрать PTT и открыть активный захват. До назначения передача
   закрыта, системное окно не открывается. Нажать «Назначить», подтвердить сочетание
   в GNOME. Выйти из голосовой комнаты и войти снова: сохранённое сочетание
   подключается без повторного «Назначить». Повторить после перезапуска приложения.
3. В другом приложении удерживать и отпускать сочетание: голос передаётся только
   во время удержания. Повторить после переключения окна и сворачивания CheenHub.
4. Переназначить сочетание; проверить изменение подписи и сохранённой настройки.
   Закрыть системное окно без изменений и нажать «Готово»; повторить с отменой
   в системном окне и кнопкой «Отменить» в клиенте. Старое сочетание остаётся.
5. Изменить и удалить сочетание через GNOME Settings при активном PTT: подпись
   меняется без перезапуска, удаление закрывает передачу и показывает сообщение.
6. Остановить захват. Сочетание перестаёт перехватываться. Назначение без активного
   захвата также освобождает сессию после завершения и отмены.
7. Быстро запускать/останавливать захват одновременно с назначением и отменой.
   Удержания предыдущего захвата или системного окна не открывают новый gate.
8. Перезапустить приложение, portal или D-Bus в изолированной тестовой сессии.
   Ошибка закрывает передачу; сохранённое действие подключается автоматически,
   после восстановления требуется новое нажатие.
   Если initial probe не удался, «Проверить снова» повторяет проверку без диалога.
9. Проверить backend v1: первое назначение и удержание работают; повторное назначение
   направляет в системные настройки без попытки вызвать ConfigureShortcuts.
