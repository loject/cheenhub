# Описания обновлений

Для каждого стабильного тега заранее подготовьте файл `releases/<точный-тег>.md`.
Описание хранится в Git вместе с кодом выпуска. Для RC файл необязателен:
без него GitHub Release получит стандартное описание. Для сборок `main` файл не требуется.

## Подготовка с Codex

Перед созданием тега попросите:

> Подготовь описание обновления для <тег> в releases/<тег>.md по изменениям
> от предыдущего стабильного релиза. Проверь коммиты и код, объедини связанные
> изменения, исключи повторы, внутренний рефакторинг и техническое обслуживание.
> В GitHub опиши пользовательские изменения всех платформ, в RuStore — только
> доступные на Android. Не обещай функций, которых нет в коде выбранного выпуска.
> Покажи текст для проверки, не публикуй релиз и не создавай тег.

Для существующего тега анализируется его код, а не текущий `HEAD`.
Предыдущая стабильная версия выбирается среди предков целевого коммита;
RC не становится началом диапазона стабильного релиза.
Если версия ещё не выпущена, целевым коммитом служит текущий `HEAD`.

Проверьте и при необходимости отредактируйте текст, затем закоммитьте описание
отдельно от инфраструктуры и кода приложения, до запуска команды выпуска.
Генерация выполняется в чате: дополнительный ключ ИИ API для CI не требуется.

## Формат файла

Первая строка — `# <точный-тег>`. Далее обязательны два непустых раздела:
`## GitHub` и `## RuStore`, каждый ровно один раз.
Другие заголовки второго уровня запрещены; внутри GitHub можно использовать
заголовки третьего уровня и Markdown. Текст RuStore пишется обычным текстом,
без расчёта на рендеринг Markdown, длиной не более 5000 Unicode-символов.
Пробелы и пустые строки по краям разделов удаляются при экспорте.

Структура:

```markdown
# v1.2.3

## GitHub

### Новое
- Пользовательское изменение для поддерживаемых платформ.

### Исправления
- Исправление с понятным пользователю результатом.

## RuStore

• Изменение, доступное пользователям Android.
• Исправление в Android-приложении.
```

## Проверка и публикация

Запускайте из корня репозитория:

```sh
cargo run -p xtask -- release-notes check v1.2.3
cargo run -p xtask -- release-notes export v1.2.3 /tmp/cheenhub-release-notes
```

Экспорт создаёт `github.md` и `rustore.txt`. Команды не вызывают внешние API.
Команда `release-version tag` проверяет описание до изменения версии и создания
тега. CI проверяет и экспортирует описание в job `prepare`, до сборок и публикаций.
Отсутствующий файл стабильного выпуска, пустой раздел, неверный тег или
превышение лимита приводят к ошибке. Если файл для RC существует, он также
должен соответствовать формату.

Из раздела GitHub создаётся описание GitHub Release. Повторная публикация
артефактов также обновляет описание существующего релиза из файла.
RuStore получает раздел RuStore при создании черновика, перед загрузкой APK
и отправкой на модерацию. Режим публикации после модерации сохраняется.
RC публикуются только в GitHub, как и раньше.

Описание опубликованного тега нельзя изменить простым добавлением файла
в `main`: повторный запуск старого workflow использует код старого тега.
Для исправления уже опубликованного описания нужна отдельная операция обновления
метаданных; эта инфраструктура предназначена для новых выпусков.
